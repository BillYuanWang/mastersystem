# Master Dance Admin Integration

This package exposes one protected administration service through three
surfaces:

1. `MasterDanceAdminSDK`: an in-process TypeScript SDK.
2. `master-dance-admin-api`: an optional localhost HTTP API documented by
   `openapi.yaml`.
3. `master-dance-mcp`: a local STDIO MCP server for Codex and ChatGPT desktop.

All three surfaces call the same service layer. They authenticate as an active
Master Dance administrator with the public Supabase client configuration, then
remain subject to Row Level Security, database validation, dependency-aware
deletion, and audit triggers. No service-role key or database password is used.

## Build

```sh
cd integrations/master-dance-admin
npm install
npm run check
npm run build
npm test
```

Generated `dist` and `node_modules` directories are ignored. Commit
`package-lock.json` so dependency versions remain reproducible.

## Store local credentials

Run this once on each authorized administrator Mac:

```sh
./script/setup_master_dance_admin_credentials.sh
```

The script asks for the Admin email and password without echoing the password.
It stores those values and a randomly generated localhost API token in macOS
Keychain. It does not write secrets to this repository, `.codex/config.toml`,
shell history, or logs.

For temporary CI or development sessions, these environment variables are also
supported:

- `MASTER_DANCE_ADMIN_EMAIL`
- `MASTER_DANCE_ADMIN_PASSWORD`
- `MASTER_DANCE_ACCESS_TOKEN`
- `MASTER_DANCE_SUPABASE_URL`
- `MASTER_DANCE_SUPABASE_PUBLISHABLE_KEY`
- `MASTER_DANCE_LOCAL_API_TOKEN`

Do not place them in a tracked file.

## MCP

This Mac's Codex MCP configuration launches:

```sh
./script/master_dance_mcp.sh
```

The registered command contains no credentials and sets the default approval policy to `writes`, so
read tools can run normally while mutations remain visible for approval. Restart
Codex after the first build or configuration change, then use `/mcp` or the MCP
settings panel to confirm `master_dance` is connected.

The MCP exposes focused CRUD, course pricing, enrollment, adult session passes, attendance, leave,
family linking, guardian invitations, contract publication, media, invoice
version, and payment tools. Tool descriptions repeat the important invariants:

- money uses integer USD cents;
- a priced group course derives its per-session rate as its full-term unit rate plus USD 5;
- private lessons use per-session pricing only;
- issued invoices, payments, signed contracts, and audit history are immutable;
- linked records cannot be silently hard deleted;
- session-pass use history is generated by attendance and is undone by clearing that attendance;
- course category remains hidden compatibility data;
- invoice corrections issue a new version instead of editing an old one.

## TypeScript SDK

Use the in-process SDK when the caller runs on the same trusted administrator
Mac:

```ts
import { createMasterDanceAdminSDK } from "@master-dance/admin-integration";

const admin = createMasterDanceAdminSDK();
const courses = await admin.listRecords("courses", {
  search: "芭蕾基训",
  limit: 50
});

await admin.runAction("set_course_pricing", {
  course_id: "COURSE_UUID",
  pricing_status: "priced",
  full_term_unit_price_cents: 4000,
  per_session_unit_price_cents: null
});
```

Read the target first and send the smallest possible write. Use stable UUIDs,
not display names, in mutations.

Guardian email and phone remain required by default. Before a guardian account
is linked, Codex or another trusted integration may make the temporary
exception explicit when source information is not yet available. The native
macOS form does not expose this exception and continues to require both fields:

```ts
await admin.createRecord(
  "guardians",
  { display_name: "Pending Family" },
  { allowIncompleteGuardianContact: true }
);
```

The MCP tools expose the same exception as
`allow_incomplete_guardian_contact`. The localhost API uses that name as a
boolean query parameter. Blank values are stored as `null`, not invented
placeholder contact data. Add a valid email and phone before issuing a guardian
invitation code.

## Local HTTP API

Start the optional API only while a trusted local integration needs it:

```sh
./script/master_dance_admin_api.sh
```

It binds to `127.0.0.1:4688` by default and refuses to start without the local
Keychain bearer token. It is not a cloud endpoint and must not be exposed by
port forwarding. Its implemented contract is in
[`openapi.yaml`](openapi.yaml).

The bundled `MasterDanceAdminApiClient` reads an explicitly supplied bearer
token and supports the same CRUD and action surface. A local app can retrieve
the token through `resolveLocalApiToken()` instead of displaying it.

## Coverage and deliberate limits

The resource catalog covers current school, profile, term, holiday, reference,
course, session, guardian, learner, enrollment, attendance, leave, contract,
adult session-pass plans/cards/uses, news, advertisement, notification, billing,
and audit records.

Some resources are intentionally read-only through generic CRUD. Their supported
write workflow is a dedicated action, or they are legal/financial history that
must never be rewritten. Storage upload accepts already prepared files; image
optimization and invoice PNG rendering remain the responsibility of the native
Mac app or another explicit artifact generator.

The session-pass resources depend on the additive Supabase migration tracked in
the repository. Supabase remains the source of truth, and both native apps
receive changes through their existing synchronization path.
